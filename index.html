Theory
MD5 Algorithm - Theory

1. Introduction

The MD5 Message-Digest Algorithm is an iterated cryptographic hash function designed by Ronald Rivest of MIT in 1991 and specified in RFC 1321. MD5 processes an arbitrary-length message and produces a fixed-size 128-bit (16-byte) message digest, conventionally represented as a 32-character lowercase hexadecimal string.

Core Property: A cryptographic hash function is a deterministic one-way mapping. For any message M, computing MD5(M) is simple, but inverting the digest is computationally intractable (preimage resistance).

2. Preprocessing and Padding

MD5 processes data in blocks of 512 bits (64 bytes). Padding is appended as follows:

  • Append 0x80: A single '1' bit followed by seven '0' bits (byte 0x80) is appended immediately after the message.
  • Append Zero Bytes: Zero bytes (0x00) are appended until the byte length satisfies: length mod 64 = 56.
  • Append 64-bit Length: The original message bit length is appended as an 8-byte little-endian integer.

3. Four 32-bit State Registers

MD5 uses four 32-bit registers initialized to RFC 1321 constants:

A = 0x67452301   B = 0xEFCDAB89   C = 0x98BADCFE   D = 0x10325476

4. Four-Round Compression (64 Operations)

Each 512-bit block passes through 64 operations across 4 rounds of 16 operations each:

5. Avalanche Effect and Strict Avalanche Criterion

The Strict Avalanche Criterion (SAC) requires that flipping a single input bit must cause approximately 50% of the 128 output bits to change. This property is verified in the Simulation tab with the 128-bit heatmap comparator.

6. Security Deprecation (RFC 6151)

Warning: MD5 is cryptographically broken for collision resistance and must NOT be used for digital certificates, SSL/TLS signatures, or password hashing in modern production systems.

In 2004, Wang and Yu demonstrated practical collisions. In 2008, chosen-prefix attacks enabled forging rogue SSL Certificate Authorities. In 2012, the Flame malware used MD5 collisions to forge code signatures. Modern systems must use SHA-256, SHA-3, or Argon2id.

  1. Open the Simulation tab to access the interactive MD5 workspace.
  2. Enter an input message (e.g., "abc" or "hello") or choose from the preset chips.
  3. Optionally toggle the Dynamic Salt / Nonce to test keyed message hashing.
  4. Click Generate MD5 Hash to run the native JavaScript MD5 algorithm.
  5. Examine the diagnostic register cards showing final chaining states A, B, C, D.
  6. Scroll to the MD5 Processing Visualizer to trace Stages 1 through 6.
  7. In the Avalanche Effect Comparator, enter two messages differing by 1 character.
  8. Observe the 128-Bit Heatmap verifying approximately 50% bit diffusion.
  9. Click the Quiz button in the Simulation tab and answer all 10 questions.
